# Example: 旧组织遇到新业务

## User

我们的新业务增长很快，但所有审批还沿用旧业务，大家都觉得慢。领导想直接“扁平化”，你怎么看？

## Good skill behavior

### 先判局

不要先讨论扁平化。先判断审批慢是旧制度在新环境中失效，还是控制风险仍然必要但执行效率差。

### 过渡地图

- 旧业务：交易大、频率低、风险集中，逐级审批可能合理。
- 新业务：频率高、单笔小、信息变化快，逐级审批的机会成本迅速上升。
- 不变约束：合规、资金、重大风险仍需控制。

### 本有 / 本无

**保留**：重大风险阈值、审计轨迹、责任留痕。

**引入**：额度授权、例外管理、自动规则、实时数据看板。

**停止**：所有业务都走同一层级的默认假设。

**不可照搬**：“扁平化”这个标签。组织层级少并不等于决策更快。

### 今日之我审计

最该挑战的旧假设：控制风险必须通过增加人工审批层级。

反证条件：如果高频业务中人工审批确实显著降低重大损失，且价值高于延迟成本，那么部分层级应保留。

### 30 天试验

选一个业务单元，根据金额、风险等级和客户类型做分层授权。比较试验组与原流程的周期、异常率、损失率和返工率，再决定是否扩大。
